# Sumo Logic Metrics Query Skill

This folder contains `sumo-metrics-query`, a Claude Agent Skill for writing and troubleshooting Sumo Logic Metrics queries — the query language used by the Sumo Logic Metrics Search API, metrics-backed monitors, and dashboard panels.

## What it does

When active, the skill gives Claude working knowledge of:

- Metrics selector syntax (key-value scoping, wildcards, negation, the `in` operator)
- The full metrics operator set — `avg`, `sum`, `min`, `max`, `count`, `pct`, `stddev`, `topk`, `bottomk`, `quantize`, `fillmissing`, `rate`, `delta`, `accum`, `eval`, `parse`, `timeshift`, `where`, `filter`, `along`
- Quantization and rollup selection (why the default `avg` rollup is often wrong, and how to pick the right one)
- Rate/counter handling patterns for ever-increasing counter metrics
- The `#A`/`#B`/`#C` + `along` pattern for computing a derived metric from two queries (the "ABC pattern")
- Cardinality and DPM (data points per minute) cost/performance management
- Tag schemas and example queries by metric source/type — Kubernetes/OpenTelemetry infrastructure metrics, trace-derived metrics (`_contenttype=metricfromtrace`), AWS CloudWatch, host metrics, and OTel application integrations

It intentionally does **not** cover the Metrics Search UI, chart panel configuration, or the log search query language — those are different concerns and different query languages.

## Expected use case

Load this skill (or point a Claude session at it) when you want help:

- Writing a new metrics query from scratch for a dashboard, monitor, or ad-hoc investigation
- Debugging a query that returns wrong, missing, or "too many timeseries" results
- Deciding on quantization/rollup settings for a specific metric
- Computing a derived metric (percentage, ratio, difference) from two source metrics
- Understanding what tags/dimensions a given metric source will have, especially trace-derived metrics that don't follow infrastructure tag conventions
- Reviewing or refactoring existing metrics queries for correctness or cardinality efficiency

It's aimed at anyone writing Sumo Logic metrics queries directly — SREs, platform engineers, dashboard/monitor authors — via the Metrics Search API or query bar, not at end users only consuming pre-built dashboards.

## Contents

- `sumo-metrics-query/SKILL.md` — entry point; core query syntax and concepts, with pointers into the reference files below
- `sumo-metrics-query/references/operators.md` — full syntax and examples for every operator
- `sumo-metrics-query/references/best-practices.md` — quantization, rates/counters, joins/along, output limits, cardinality/DPM, and general query-writing tips
- `sumo-metrics-query/references/metric-types.md` — tag schemas and example queries by metric source (Kubernetes/OTel, trace-derived, CloudWatch, host, OTel application metrics)
- `sumo-metrics-query.skill` — the same skill packaged as a zip, for installing into another Claude Code / Cowork setup

## Provenance and status

**This skill is experimental.** It was generated by Claude, based on:

- Sumo Logic's public Metrics documentation (metrics-queries, metrics-operators, and metric-query-best-practices docs at sumologic.com/help)
- An internal Sumo Logic Customer Success training deck ("Metric Query Tips, Tricks and Best Practices")

It has not been formally reviewed or validated against a live Sumo Logic environment. Treat its query examples and guidance as a strong starting point rather than an authoritative reference, and verify against current Sumo Logic documentation and your own environment before relying on it for production use.
